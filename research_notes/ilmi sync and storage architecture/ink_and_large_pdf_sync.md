Reading notes for the report writer:

- Every finding carries the date of its source where one was visible. "Fetched" means the page was opened and read; "search summary" means the fact came from a search-result digest and the page itself was not opened (several vendor support sites returned 403/429). Treat search-summary facts as less certain.

## 1. Storage formats and sync architectures of the established handwriting and PDF-annotation apps

### Takeaway
The two market leaders have both moved (2024–2026) from "the user's iCloud via CloudKit" to a vendor-run cloud with an account: Goodnotes Cloud (Pro plan, AWS, CRDT + event sourcing, still a pilot on iOS) and Notability Cloud (free, replaces iCloud sync); Notewise is dropping iCloud sync too. None of the commercial apps keeps user-readable plain files as the synced source of truth; the file-based apps (Xournal++, Rnote, Saber) sync whole per-note files and have no stroke-level merge.

### Cited Findings

**Goodnotes (5, 6 and the cross-platform app)**

- GoodNotes 5 adopted CloudKit for iCloud sync when it replaced GoodNotes 4: "we adopted the latest CloudKit technology to power iCloud sync" (post dated 13 Jan 2021, fetched). Local notes are kept on device and not re-downloaded on each launch. — [Goodnotes blog](https://www.goodnotes.com/blog/how-goodnotes-keep-your-digital-notes-safe)
- Goodnotes engineers describe the stack as "local first sync using CRDT + event sourcing", with "large in-house tech stacks around many things such as rendering, ink engine", shared cross-platform "using Swift WASM"; one engineer is "syncing data across platforms with Goodnotes Cloud" and names the difficulty of "supporting both iCloud and Goodnotes Cloud"; another is "improving the real-time collaboration code to support large classes" (post dated 16 May 2024, fetched). — [Goodnotes blog: life as an iOS engineer](https://www.goodnotes.com/blog/behind-the-scenes-life-as-an-ios-engineer)
- Swift.org post by a Goodnotes engineer (1 June 2026, fetched): the same Swift code powers iOS and the web via WebAssembly; shared Swift is 1.47 million lines (66% of the web app, 34% of the iOS app); the shared code includes document modelling, document synchronisation and "conflict resolution using Conflict-Free Replicated Data Types (CRDTs)"; rendering is "a custom rendering engine built on low-level graphics APIs: Metal on iOS and WebGL on the web" (PencilKit is not used); the Wasm binary is about 50 MB uncompressed, about 12 MB with Brotli. — [Swift.org](https://swift.org/blog/bringing-goodnotes-to-web-with-swift/)
- web.dev case study (undated, references NSSpain 2023, fetched): web, Android and Windows versions are a PWA reusing the Swift code through SwiftWasm (Windows via PWABuilder, Android via Trusted Web Activities); IndexedDB was "a huge enabler for the collaborative offline experience on the web"; "Goodnotes solved this problem long ago by using" CRDTs; views, API clients and database access were reimplemented in TypeScript. — [web.dev](https://web.dev/case-studies/goodnotes)
- Goodnotes Cloud (state in 2026): syncs the library across Apple, Android, Windows and Web devices signed in to the same Goodnotes account; included with Goodnotes Pro, not with Essential or Special Edition; on iOS it is being rolled out gradually and requires enrolment in the "Goodnotes Cloud iOS pilot program"; iCloud Sync remains Apple-only and uses the user's iCloud quota (search summary of the support article, which returned 403; FAQ page fetched). — [Goodnotes support](https://support.goodnotes.com/hc/en-us/articles/10277366719759-Sync-your-Goodnotes-library-across-all-platforms-with-Goodnotes-Cloud); [Goodnotes Cloud FAQ](https://go.goodnotes.com/support/goodnotes-cloud-faqs)
- Goodnotes Cloud FAQ (© 2026, fetched): infrastructure uses third-party providers "such as Amazon Web Services"; data is "securely stored and encrypted" (end-to-end encryption is not claimed); the page states no storage quota, file-size limit, or conflict rule. — [Goodnotes Cloud FAQ](https://go.goodnotes.com/support/goodnotes-cloud-faqs)
- Switching rules (search summary): the iCloud library must finish syncing without errors before switching to Goodnotes Cloud; switching back to iCloud blocks switching again for a period (one help page says 6 months); a device still holding an iCloud library shows "Goodnotes Cloud Sync Disabled". — [Goodnotes support](https://support.goodnotes.com/hc/en-us/articles/10277366719759-Sync-your-Goodnotes-library-across-all-platforms-with-Goodnotes-Cloud)
- iCloud sync failure modes Goodnotes documents (search summary): not enough iCloud storage; Apple outage; documents that stay greyed out because "interrupted syncing might have damaged those documents"; sync stopping when devices run different app versions. — [Goodnotes: Troubleshoot iCloud Sync](https://support.goodnotes.com/hc/en-us/articles/7352796404495-Troubleshoot-iCloud-Sync-issues-in-Goodnotes); [Goodnotes: Fix iCloud Sync](https://support.goodnotes.com/hc/en-us/articles/7353717414927-Goodnotes-on-iPadOS-iOS-is-not-syncing-with-the-Mac-app)
- User complaints (anecdotal, feedback forum): the 5 GB default iCloud allowance makes it hard to keep space; sync size grows with use and users on small devices turn iCloud sync off; a long-standing request for selective sync. — [Goodnotes feedback: selective iCloud sync](https://feedback.goodnotes.com/forums/191274-customer-suggestions-for-goodnotes/suggestions/12335706-selective-icloud-sync); [Goodnotes feedback: cloud storage on Essential](https://feedback.goodnotes.com/forums/191274-customer-suggestions-for-goodnotes-apple/suggestions/50712881-fix-cloud-storage-on-essential-plan)
- `.goodnotes` export format (community reverse engineering, fetched; undocumented by the vendor): a ZIP container holding `index.*.pb` (Protobuf page/document indexes), `schema.pb` (schema version 24 or 25), `attachments/<UUID>` (embedded images, audio, PDFs, no extensions), and `notes/<UUID>` files holding page strokes in Troy Hanson TPL format compressed with LZ4; "no reliable open-source writer" exists. — [hermes-goodnotes README](https://github.com/Emilthesleeper/hermes-goodnotes)
- Backup: auto-backup to Dropbox, Google Drive or OneDrive saves a copy of each document and "will automatically replace that copy in your cloud storage" on each edit (PDF is an option); manual backup is a .zip of the library; auto-backup is one-way, not sync (2021 post fetched; search summary for the one-way statement). — [Goodnotes blog](https://www.goodnotes.com/blog/how-goodnotes-keep-your-digital-notes-safe); [Goodnotes for Business help](https://goodnotesforbusiness.zendesk.com/hc/en-us/articles/12201943307023-How-to-use-Auto-Backup-to-automatically-create-a-copy-of-your-documents-in-a-supported-cloud-storage)
- Pricing (pricing page fetched, © 2026): Free $0 (up to 3 files, 5 MB import limit, 20 minutes of audio); Essential $11.99/year; Pro $35.99/year (adds cross-device sync between Apple and non-Apple devices, real-time collaboration, Drive integration, AI); Teams $120 per seat/year; AI Pass add-on +$9.99/month; Special Edition is a one-time purchase, Apple only, price not listed, "not eligible for Goodnotes Cloud". — [Goodnotes pricing](https://www.goodnotes.com/pricing)
- Conflicting price reports: a 2026 Setapp comparison cites a one-time $29.99 for Goodnotes 6 (search summary); an aggregator cites Special Edition at $35.99 one-time (search summary). The vendor page lists no one-time price. — [Setapp](https://setapp.com/app-reviews/goodnotes-vs-notability); contradicted or left open by [Goodnotes pricing](https://www.goodnotes.com/pricing)
- A support article comparing plans is reported (search summary only) as giving the free tier 100 MB of storage and Essential 5 GB; the pricing page itself states no storage quotas. — [Goodnotes: Compare plans](https://support.goodnotes.com/hc/en-us/articles/13808767840015-Compare-Goodnotes-Plans-and-Features); not confirmed by [Goodnotes pricing](https://www.goodnotes.com/pricing)
- Handwriting search: Goodnotes search covers handwriting, typed text and text in PDFs; Goodnotes "does not perform OCR on imported PDFs", so an imported scan needs its own text layer; users see "Indexing x pages for search" and incomplete results until indexing finishes (search summary of vendor help pages). One blog tester reports search worked with Wi-Fi off, i.e. on device (anecdotal). — [Goodnotes help: Search](https://goodnotes-team.notion.site/Search-Handwriting-and-Math-Recognition-26fb740273d281b5beb8e60130afb556); [buralog](https://buralog.jp/en/ipad-handwriting-search-en/)

**Notability**

- Notability Cloud (FAQ fetched, undated, current in 2026): "our own cloud infrastructure that keeps your notes synced across all your devices and platforms", covering iOS, Android, Mac and Web; "free for all users"; notes keep syncing after a subscription lapses; "Edit offline, sync when you're back online"; syncs all notes, folders and recordings; enables Live Collaboration; storage is described only as "generous"; new users are set up on it automatically, existing users get an in-app prompt (iPad first; "A Mac update is coming soon"); after switching, "iCloud is no longer used for syncing" but iCloud Version History and note restoration still rely on the old iCloud data; unavailable in mainland China, Hong Kong and Macau. — [Notability Cloud FAQ](https://support.gingerlabs.com/hc/en-us/articles/9598417028378-Notability-Cloud-FAQ)
- The vendor's claim for the move: "Most users find sync noticeably more reliable after switching." — [Notability Cloud FAQ](https://support.gingerlabs.com/hc/en-us/articles/9598417028378-Notability-Cloud-FAQ)
- A Paperlike review (published 19 Aug 2026, updated 7 Oct 2026, fetched) states for Notability "iCloud is no longer supported" and that Goodnotes library sync across platforms needs Goodnotes Cloud, "still in pilot". — [Paperlike](https://paperlike.com/blogs/paperlikers-insights/app-review-goodnotes-vs-notability)
- Notability for Android: waitlist and beta reported for April 2026; Android notes sync only through Notability Cloud, not to third-party backup services (search summary). — [Android Central](https://www.androidcentral.com/apps-software/android-notability-waitlist-april-2026); [Notability Android FAQ](https://support.gingerlabs.com/hc/en-us/articles/11084032368538-Notability-for-Android-FAQ)
- Notability general FAQ (dated 31 Aug 2026, fetched): iCloud "syncs notes across multiple devices" but is not a backup; third-party backup copies notes to a cloud storage service, and deleting a note does not delete its backup. — [Notability FAQ](https://support.gingerlabs.com/hc/en-us/articles/360010811331)
- `.note` format (reverse-engineered 31 Mar 2018, fetched; may have changed since): a ZIP archive with `Session.plist` (binary plist), `metadata.plist`, `Recordings/library.plist`, `Assets`, `Images`, thumbnails; strokes are base64 arrays in the plist: `curvespoints` (32-bit float x,y pairs), `curvesnumpoints`, `curveswidth`, `curvescolors` (RGBA), `curvesfractionalwidths`. — [Julia Evans](https://jvns.ca/blog/2018/03/31/reverse-engineering-notability-format/)

**Apple Notes and Freeform**

- Freeform is one of the system apps built on CKSyncEngine (WWDC23, search summary of the session); the session does not say Freeform uses a CRDT. — [WWDC23: Sync to iCloud with CKSyncEngine](https://developer.apple.com/videos/play/wwdc2023/10188/)
- CloudKit itself offers record-version checks and leaves conflict resolution to the app (VLDB 2018 paper, search summary). — [CloudKit paper](https://www.vldb.org/pvldb/vol11/p540-shraer.pdf)
- Apple Notes is reported to use CRDTs internally for syncing (objc.io episode; a 2020 arXiv paper says so "based on introspection of the runtime headers"); neither describes drawing merges (search summaries). — [objc.io](https://talk.objc.io/episodes/S01E294-crdts-introduction); [arXiv 2006.09823](https://arxiv.org/pdf/2006.09823)
- In the Notes database a drawing attachment's bytes sit in the `ZMERGEABLEDATA1` column (`ZMERGEABLEDATA` on older schemas) for `com.apple.drawing` and `com.apple.drawing.2` attachments, and Apple's public `PKDrawing(data:)` decodes them (third-party project, 2026, search summary). A forensic series documents the same column as holding embedded protobuf and shows a `FallbackImages` path for drawing attachments. — [apple-notes-mcp PR #230](https://github.com/sweetrb/apple-notes-mcp/pull/230); [Ciofeca Forensics](https://ciofecaforensics.com/2020/09/18/apple-notes-revisited-protobuf/)
- Notes stores a pre-rendered thumbnail beside markup and shows it when the data's content version is newer than the device supports: "Displaying this thumbnail in the case of a version mismatch is considered the best practice, and it is exactly what apps like Notes are using" (WWDC25, fetched). — [WWDC25: Meet PaperKit](https://developer.apple.com/videos/play/wwdc2025/285/)

**PDF-reading-and-annotation apps**

- MarginNote 4: annotations live in MarginNote's own study-set/notebook data, not in the PDF; forum users report the notebook and annotations syncing through iCloud while the PDF file did not, and the reverse (PDF shared, annotations not); iCloud sync described as "inconsistent and at times unreliable" (forum posts, anecdotal, search summary). — [MarginNote forum: PDF shared, annotations not](https://forum.marginnote.com/t/icloud-sync-issue-pdf-is-shared-but-annotations-are-not/10578); [MarginNote forum: MN4 sync](https://forum.marginnote.com/t/marginnote-4-sync/9131); [MarginNote forum: Mac/iPad sync issue](https://forum.marginnote.com/t/sync-issue-between-macbook-and-ipad-in-marginnote-4/10373)
- LiquidText: its paid LIVE tier gives real-time sync and continuous cloud backup on the vendor's own infrastructure built on Microsoft Azure; a separate tier connects to Dropbox, Box, OneDrive and iCloud; users refer to project files (`.ltproj` per a forum thread) kept in iCloud (search summary). — [LiquidText pricing/features](https://liquidtext.net/pricing-features); [RWS Magazine](https://rwsmagazine.com/liquidtext-launches-real-time-interoperability-among-devices/); [MacPowerUsers](https://talk.macpowerusers.com/t/liquidtext-just-launched-sync-service/24909)
- Zotero's reader: annotations are stored in Zotero's SQLite database and synced as small records, not written to the PDF (details in section 4). — [Zotero KB](https://www.zotero.org/support/kb/annotations_in_database)

**Open-source, file-based apps**

- Xournal++: `.xopp` is gzip-compressed XML, close to Xournal's `.xoj`; a PDF background is referenced, not stored in the file, so deleting the PDF loses the background; the project describes a new file format in development that can store attached PDFs internally (search summary of README text from a fork). — [Xournal++ README (fork)](https://github.com/panpaul/xournalpp)
- Rnote: `.rnote` is gzip-compressed JSON (flate2 + Serde); the README says "the file format is still unstable. It might change and break compatibility between versions"; a draft PR proposed zstd + bitcode with separated version metadata (search summary). — [flxzt/rnote](https://github.com/flxzt/rnote)
- Saber: current format `.sbn2` is BSON with embedded assets (legacy `.sbn` was JSON; `.sba` is a ZIP of note plus assets); Nextcloud sync is file-level and bidirectional with encrypted remote paths and AES-256 encryption (unofficial auto-generated wiki, search summary). A user syncing with Syncthing reported an unopenable note and an import creating `note (2).sbn2` (anecdotal). — [DeepWiki: Saber file management and sync](https://deepwiki.com/saber-notes/saber/4-file-management-and-synchronization); [Saber issue #1242](https://www.github.com/saber-notes/saber/issues/1242)

**Whiteboards (how strokes are merged)**

- Excalidraw (post of 29 Mar 2020, fetched): each peer merges by taking the union of local and incoming elements by ID; each element has a `version` incremented on change, and the higher version wins; ties are broken by a random `versionNonce` (lower wins) so that "one player will deterministically 'win' on every peer"; deletion is a tombstone flag `isDeleted`, dropped when saving to persistent storage; the server only relays end-to-end-encrypted messages. — [Excalidraw blog](https://plus.excalidraw.com/blog/building-excalidraw-p2p-collaboration-feature)
- tldraw sync (docs fetched): a `TLSocketRoom` "stores the authoritative copy of the document, relays changes between sync clients over WebSockets"; one room instance per document (Cloudflare Durable Objects); document state persists in SQLite; "large binary assets like images and videos" go to a separate asset store (R2). A third-party analysis describes the model as server-authoritative push/pull/rebase over records, not a CRDT (search summary). — [tldraw docs](https://tldraw.dev/docs/sync); [Grida research note](https://grida.co/docs/wg/research/crdt/tldraw)

### Inferences
- The direction of travel among commercial apps is away from the user's iCloud and towards a vendor account and vendor servers; the stated or implied reasons are cross-platform reach, collaboration, quota independence and reliability. Three independent vendors (Goodnotes, Notability, Notewise) made the same move within roughly two years.
- Goodnotes is the only vendor found that publicly states a CRDT design for ink documents; it does not use PencilKit, which is consistent with needing the same ink engine on web, Android and Windows.
- Every app that splits "small annotation records" from "large PDF binary" (Zotero, MarginNote, tldraw's asset store) ends up with two sync paths, and user reports for MarginNote show the two paths can drift apart (one arrives, the other does not).
- Vendor-run sync is always paired with a second, user-visible escape route (auto-backup to Drive/Dropbox, PDF export, .zip backup). The backup is one-way and whole-file.

### Gaps
- No Goodnotes engineering post describing the sync protocol, the CRDT type used for strokes, the event log layout, or the CloudKit record design was found; only the one-line descriptions above.
- No vendor statement of Goodnotes Cloud or Notability Cloud storage quotas or per-file limits was found.
- Nothing reliable was found for Samsung Notes, Concepts, Notes Writer, Kilonotes or Flexcil storage and sync; Okular's docdata was not reached.
- How Apple Notes or Freeform merges two concurrent edits to the same drawing is not documented in any source found.
- The current (2026) Notability `.note` internals were not verified; the only description is from 2018.

## 2. PencilKit data: properties relevant to storage, merging and cross-platform use

### Takeaway
A PKDrawing is an ordered array of strokes serialised to an opaque, versioned, lossily compressed blob that only Apple platforms can read; it can be decoded and rendered on macOS, but the interactive canvas exists only on iOS, iPadOS, Mac Catalyst and visionOS. Apple's current documentation shows each stroke carrying a UUID, which is the hook for a stroke-set merge, but Apple documents only "append", not a merge, and the serialised bytes are not stable for byte comparison.

### Cited Findings

- `PKDrawing` is available on iOS 13+, iPadOS 13+, Mac Catalyst 13+, macOS 10.15+ and visionOS 1+; API includes `init(data:)`, `init(strokes:)`, `dataRepresentation()` ("Returns a raw data representation of the rendered content"), `strokes`, `bounds`, `image(from:scale:)` returning `UIImage` or `NSImage`, `draw(in:frame:from:darkUserInterfaceStyle:)` into a `CGContext`, `transform(using:)`, `append(_:)` ("Appends the contents of the specified drawing object to an existing drawing object"), `appending(_:)`, `erasePath`/`erasingPath`, and `requiredContentVersion`; it conforms to `Codable` and `Equatable` (Apple docs, fetched Nov 2026). — [Apple: PKDrawing](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct)
- `PKCanvasView` is available on iOS 13+, iPadOS 13+, Mac Catalyst 13.1+ and visionOS 1+; macOS (AppKit) is not listed. It is a `UIScrollView` subclass, exposes `drawing`, `tool`, `drawingPolicy`, `isRulerActive`, `maximumSupportedContentVersion`, a delegate for change callbacks, and `selection: Set<UUID>` ("The identifiers of the strokes selected on the canvas") (Apple docs, fetched Nov 2026). — [Apple: PKCanvasView](https://developer.apple.com/documentation/pencilkit/pkcanvasview)
- `PKStroke` (iOS 14+, macOS 11+) has `path`, `ink`, `transform`, `mask`, `maskedPathRanges`, `renderBounds`, `randomSeed`, `requiredContentVersion`, and, in the current docs, `id: UUID` ("The unique identity of the stroke"), `renderGroupID: UUID?`, `renderState`, `substroke(range:)`, and an initialiser taking `id:`; it conforms to `Identifiable` and to PaperKit's `Markup` (Apple docs, fetched Nov 2026; the OS version that introduced `id` was not shown on the page). — [Apple: PKStroke](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct)
- A third-party API reference states that `init(strokes:)` resolves duplicate stroke IDs by generating new UUIDs for the conflicting strokes (search summary; not confirmed in Apple's text). — [onestack.dev PKDrawing reference](https://onestack.dev/ios-reference/PencilKit/PKDrawing)
- Content versions (`PKContentVersion`, iOS 17+/macOS 14+): `version1` = inks from iPadOS 14 and earlier (marker, pen, pencil); `version2` = iPadOS 17 inks (monoline, fountain pen, watercolor, crayon); `version3` = barrel-roll angle data; `version4` = Reed Pen ink; `version5` = "stroke render state support"; `latest`. A canvas can be capped with `maximumSupportedContentVersion` (Apple docs, fetched Nov 2026). — [Apple: PKContentVersion](https://developer.apple.com/documentation/pencilkit/pkcontentversion)
- A drawing that uses newer inks cannot be loaded by an older PencilKit; a developer reported a "too new" format error when reloading a drawing saved with iOS 17 inks (forum report, search summary, resolution unconfirmed). — [Apple Developer Forums, PencilKit tag](https://developer.apple.com/forums/tags/pencilkit?page=4)
- Data model (WWDC20, fetched): a drawing is "composed out of many PencilKit strokes", "in the order that the user drew them"; a stroke has path, ink, transform and mask; "A PencilKit stroke path is a uniform cubic B-spline of PencilKit stroke points"; points carry location, size, azimuth, opacity, force, altitude and time offset; "These points are stored in a lossily compressed format, so any points you create will not capture the values you use with perfect precision." — [WWDC20: Inspect, modify, and construct PencilKit drawings](https://developer.apple.com/videos/play/wwdc2020/10148/)
- Erasing changes stroke identity (WWDC20, fetched): the pixel eraser produces masked strokes; masks "can have holes" or "cut a stroke into multiple pieces", and each piece "become[s] unique, independent strokes". — [WWDC20 session 10148](https://developer.apple.com/videos/play/wwdc2020/10148/)
- Serialisation is not canonical: a PencilKit guide warns that the same visual drawing can produce different bytes, so comparing `dataRepresentation()` output is unreliable; another developer notes serialising costs CPU and memory that grows with stroke count (third-party guide and a GitHub PR, search summaries). — [PencilKit skill guide](https://skills.lc/dpearson2699/swift-ios-skills/dpearson2699-swift-ios-skills-skills-pencilkit-drawing-skill-md); [pqp PR #1225](https://github.com/rafaelcg/pqp/pull/1225)
- The stroke-point wire structure seen inside Apple Notes is a series of `PKCompressedStrokePoint` structures with timestamp, position, radius and force (Hacker News discussion of the forensic series, search summary). — [Hacker News](https://news.ycombinator.com/item?id=24533249)
- Tool picker (WWDC20, fetched): from iOS 14 an app can create its own `PKToolPicker` instances; "PKCanvasView support for Catalyst" was added but "The tool picker is not supported" there, and inks are set through the canvas API; `drawingPolicy` has `.anyInput`, `.pencilOnly` and `.default`; smart selection (double-tap word/line, brush-to-select), Insert Space and the system colour picker come to existing PencilKit clients with "no adoption". — [WWDC20: What's new in PencilKit](https://developer.apple.com/videos/play/wwdc2020/10107/)
- PaperKit (WWDC25, fetched): "provides a canvas that you can both draw on and add a variety of markup elements to, including shapes, images, textboxes, and much more"; `PaperMarkupViewController` edits, `PaperMarkup` is the data container that "handles saving and loading both the PaperKit markup and PencilKit drawing data"; saved with `dataRepresentation()`; a change delegate (`paperMarkupViewControllerDidChangeMarkup`) is the suggested auto-save point; on macOS ("new to macOS Tahoe") there is a `MarkupToolbarViewController`; content version must be checked on load. — [WWDC25: Meet PaperKit](https://developer.apple.com/videos/play/wwdc2025/285/)
- A developer note says PaperKit is not available on Mac Catalyst (one project's issue text, search summary; not an Apple statement). — [inkwell issue #17](https://github.com/lucaclo/inkwell/issues/17)
- Tauri v2 iOS plugins (docs fetched): a Swift plugin's `load(webview: WKWebView)` hook receives the web view; commands are `@objc` functions taking `Invoke`, parse arguments with `invoke.parseArgs`, return with `invoke.resolve`, and can push events to JS with `trigger(...)`; the plugin is a Swift package. The page does not document adding native views or presenting view controllers. — [Tauri: mobile plugin development](https://v2.tauri.app/develop/plugins/develop-mobile/)
- Existing wrappers: `react-native-pencil-kit` (a native view component exposing PencilKit) and `munim-pencilkit` (Turbo Module); a LogRocket tutorial bridges a native view manager around `PKCanvasView`. No Tauri or Capacitor PencilKit plugin was found (search summary). — [react-native-pencil-kit](https://github.com/mym0404/react-native-pencil-kit); [LogRocket](https://blog.logrocket.com/build-react-native-drawing-app-pencilkit)
- Web alternative, Safari/WKWebView pointer events: Safari 18.2 (late 2024) added `PointerEvent.getCoalescedEvents()` and `getPredictedEvents()` (search summary of the WebKit post). Before that, a forum thread (replies Sep and Nov 2023, fetched) reported `pointermove` delivering Apple Pencil input at 240 Hz on an iPad Pro (iPadOS 17.0.1), 120 Hz in Low Power Mode; tips were to disable Scribble for reliable `pointerdown`, disable Safari's "Prefer Page Rendering Updates near 60fps", and use `canvas.getContext('2d', {desynchronized: true})`; "Pointer events are dropped on slow animation frames". No latency figures were given. — [WebKit: Safari 18.2 features](https://webkit.org/blog/16301/webkit-features-in-safari-18-2/); [Apple Developer Forums thread 689375](https://developer.apple.com/forums/thread/689375)
- The Pointer Events spec leaves coalescing and prediction algorithms to the browser; predicted points are meant to let apps "draw ahead" and then discard them. — [W3C Pointer Events 3](https://www.w3.org/TR/pointerevents3/)

### Inferences
- With stroke UUIDs exposed, a merge of two versions of one page can be computed outside PencilKit as set operations on stroke IDs (union of additions, minus recorded removals) and rebuilt with `PKDrawing(strokes:)`. The catch is the pixel eraser, which replaces one stroke with several new ones, so an erase is "remove one ID, add N IDs" and two devices erasing parts of the same stroke will each keep their own fragments unless removals are tracked.
- Because `dataRepresentation()` is not byte-stable and is lossy-compressed, a `.pkdrawing` file should be treated as a binary that changes wholesale on every save; git cannot diff or merge it, and "is this the same drawing" must be decided by stroke IDs or a stored revision marker, not by hashing bytes.
- The planned pair of files (PNG + PKDrawing) matches Apple's own practice in Notes (data plus a pre-rendered fallback image for version mismatch), and the PNG also covers the Mac, where a Tauri (non-Catalyst) app can decode and render a PKDrawing through PencilKit but has no PKCanvasView for editing. PaperKit on macOS 26 is the only first-party route to native ink editing in an AppKit app.
- Capping `maximumSupportedContentVersion` is the available lever for keeping drawings readable on older devices in the same library.
- A PKCanvasView placed above a WKWebView is a normal UIKit subview arrangement and the Tauri plugin API hands the plugin the web view, but this is not documented by Tauri and no existing plugin was found, so it must be proven by building it.

### Gaps
- No Apple documentation or WWDC statement was found that describes PKDrawing as mergeable, or that explains what `append` does with duplicate stroke IDs; the "append on top" wording is all that is documented. The claim that Apple Notes merges concurrent drawing edits stroke-by-stroke could not be sourced.
- The OS release that introduced `PKStroke.id`, `renderGroupID` and `PKCanvasView.selection` was not verified.
- No measured latency comparison between PencilKit and a web canvas with Pencil in WKWebView was found; no source confirmed palm-rejection behaviour for pointer events in WKWebView.
- No source confirmed whether shape recognition (draw-and-hold) or handwriting recognition is available to third-party apps through PKCanvasView; no public handwriting-recognition API was found in the PencilKit pages read.
- PKDrawing data cannot be read off Apple platforms by any documented or open-source decoder found in this research; this is an absence of evidence, not a confirmed impossibility.

## 3. Alternatives to opaque PKDrawing for the stored strokes

### Takeaway
Open stroke formats exist (InkML, SVG paths, Xournal++ XML, Rnote JSON, Excalidraw/tldraw JSON, perfect-freehand point lists), but none is a shared standard that handwriting apps actually exchange, and converting PKDrawing to any of them loses PencilKit's ink rendering; the realistic open companion to a PKDrawing is a rendered image or PDF.

### Cited Findings

- InkML became a W3C Recommendation on 20 September 2011; its unit is the trace, "a sequence of contiguous ink points"; its goal is to store raw ink, not context; Microsoft and Openstream filed implementation reports (search summary). — [W3C InkML](https://www.w3.org/TR/InkML)
- perfect-freehand (MIT, fetched): input is an array of `[x, y, pressure]` points, output is an outline polygon to be drawn as an SVG path or on canvas; options `size`, `thinning`, `smoothing`, `streamline`, `simulatePressure`; ports exist in Dart, Python and Rust. — [perfect-freehand](https://github.com/steveruizok/perfect-freehand)
- Xournal++ `.xopp` is gzip XML (readable after decompression); Rnote `.rnote` is gzip JSON but declared unstable between versions. — [Xournal++ README (fork)](https://github.com/panpaul/xournalpp); [flxzt/rnote](https://github.com/flxzt/rnote)
- Excalidraw's element list is plain JSON with per-element `version`, `versionNonce` and `isDeleted`. — [Excalidraw blog](https://plus.excalidraw.com/blog/building-excalidraw-p2p-collaboration-feature)
- PKDrawing exposes enough to export: stroke paths can be sampled with `interpolatedPoints(strideBy:)`, each point has location, size, opacity, force, azimuth, altitude and time offset; but iterating the path directly yields B-spline control points that "are not actually on the stroke", and masks from the pixel eraser must be applied through `maskedPathRanges` (WWDC20, fetched). — [WWDC20 session 10148](https://developer.apple.com/videos/play/wwdc2020/10148/)
- Rebuilding PencilKit ink from other data is partial: a forum answer says ink strokes can be recreated by constructing new PKStrokes from point/path/ink data, but there is no API to turn image data into a PKDrawing and no way to migrate eraser paths (search summary). — [Apple Developer Forums thread 650565](https://developer.apple.com/forums/thread/650565)
- PKDrawing can render itself to an image (`image(from:scale:)`) or into a `CGContext` (`draw(in:frame:from:darkUserInterfaceStyle:)`), which is the route to PNG or a PDF page. — [Apple: PKDrawing](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct)

### Inferences
- For a "plain files other tools can read" philosophy the honest position is: the PNG (or a PDF/SVG render) is the open, durable artefact; the `.pkdrawing` is an editability cache that only Apple devices can open. A third file in an open stroke format (sampled points with width and colour as JSON or SVG paths) would make strokes readable elsewhere but would not round-trip PencilKit's textured inks (pencil, crayon, watercolor) and would roughly double storage for the page.
- A text stroke format (one stroke per line or per JSON object, keyed by stroke UUID) is the only representation in this list that git could merge line-wise; PKDrawing bytes and gzip containers (.xopp, .rnote) cannot be merged by git.
- If ilmi ever wants ink on a non-Apple platform, the Goodnotes precedent says an own ink engine and own format is what that takes.

### Gaps
- No evidence was found of any mainstream iPad note app importing or exporting InkML.
- No measured size comparison between PKDrawing bytes and an equivalent SVG/JSON stroke export was found.

## 4. PDF annotation storage: writing into the PDF versus sidecar files

### Takeaway
Writing ink into the PDF means rewriting the whole file on every save with Apple's PDFKit (no incremental save), which is hostile to both sync and large files; the reference managers and study apps that sync well (Zotero, MarginNote) keep annotations outside the PDF and offer "export a copy with annotations" instead. Sidecars stay attached either by living next to the file under its name (breaks on rename unless moved together) or by content hash (survives rename, breaks on any modification of the PDF).

### Cited Findings

- Zotero's stated reasons (KB, fetched): database storage "allows for fast, conflict-free syncing, including in groups"; with annotations in the file, two people annotating or a PDF left open elsewhere "would create an unresolvable file conflict, forcing the user to choose one side or the other"; and "the entire PDF file needs to be transferred after every change", which can be many megabytes versus an effectively instant single-annotation transfer; annotations can be embedded in an exported copy at any time and "will never be locked in Zotero". — [Zotero KB](https://www.zotero.org/support/kb/annotations_in_database)
- Zotero annotation position is stored as a JSON string with a page index and rectangles, for example `{"pageIndex":8,"rects":[[68.604,246.586,174.372,267.047]]}`; annotations are child items of the PDF attachment item (forum posts, search summary). — [Zotero forums](https://forums.zotero.org/discussion/132273/feature-request-expose-api-for-programmatic-pdf-annotation-creation-highlights-notes)
- PDFKit has no incremental save: an Apple forum answer says there isn't a way to update a PDF file in place; a second thread asking for incremental save (to preserve a signature) found no flag on `write` or `dataRepresentation` (search summary). — [Apple Developer Forums 763371](https://developer.apple.com/forums/thread/763371); [Apple Developer Forums 761229](https://developer.apple.com/forums/thread/761229)
- A PencilKit-on-PDF open-source app reports "PDFs grow a little with every saved drawing" because PDFKit on iOS rewrites every object and leaves old strokes unreferenced in the file; building a fresh PDFDocument from copied pages stays compact but loses bookmarks, forms and page labels (single project issue, search summary). — [notebook issue #244](https://github.com/lukaskaibel/notebook/issues/244)
- The PDF format itself supports incremental saves (append new objects and a new xref section) without rewriting the document; this must be implemented outside Apple's PDFKit (vendor article, search summary). — [Nutrient: incremental and full save](https://www.nutrient.io/blog/incremental-and-full-save-in-pdfs/)
- An Apple forum thread exists titled "PDFKit Zoom Performance Issue with Many Annotations" (title only; contents not read). — [Apple Developer Forums 802728](https://developer.apple.com/forums/thread/802728)
- Skim (macOS): "Notes and highlights you add to a PDF document are not saved in the PDF data, but are added to the file as extended attributes"; other viewers do not see them unless the user exports a copy with embedded notes; Skim can also save notes to a separate `.skim` file or wrap PDF and notes in a PDF bundle (manual, search summary). — [Skim manual: other viewers](https://skim-app.sourceforge.io/manual/SkimHelp_41.html); [Skim manual: separate file](https://skim-app.sourceforge.io/manual/SkimHelp_39.html)
- Extended attributes are fragile in transit: Skim's manual has a page on emailing a PDF losing notes, and a Zotero user reported import stripping them (anecdotal). — [Skim manual: emailing loses notes](https://skim-app.sourceforge.io/manual/SkimHelp_37.html); [Zotero forums](https://forums.zotero.org/discussion/comment/208168)
- KOReader offers three sidecar locations: next to the book (default `.sdr` folder), a central `docsettings` directory keyed by path, or `hashdocsettings` keyed by "the partial md5 hash of each document" so books can be moved or renamed without losing highlights; a maintainer warns that in hash mode "if you modify a document you're reading, its metadata will get unlinked" (search summary). — [KOReader issue #11773](https://github.com/koreader/koreader/issues/11773); [KOReader issue #9265](https://github.com/koreader/koreader/issues/9265); [kobo.koplugin docs](https://ogkevin.github.io/kobo.koplugin/dev/database/koreader/01-docsettings.html)
- Xournal++ references the background PDF by path; if the PDF is deleted the background is lost (search summary). — [Xournal++ README (fork)](https://github.com/panpaul/xournalpp)
- MarginNote keeps annotations out of the PDF, and its two data kinds (PDF file, annotation database) are reported to sync independently and sometimes inconsistently (anecdotal). — [MarginNote forum](https://forum.marginnote.com/t/icloud-sync-issue-pdf-is-shared-but-annotations-are-not/10578)

### Inferences
- ilmi's rule "the PDF itself is never modified" is the same decision Zotero, MarginNote, Skim and KOReader made, for the reasons Zotero spells out: an immutable PDF is transferred once, never conflicts, and can be deduplicated by content hash.
- An immutable PDF makes a content hash a safe identity. KOReader's failure mode (hash link breaks when the file is modified) does not arise if nothing ever writes to the PDF; the remaining case is the user replacing the file with a new edition, which is a genuinely different document.
- Path-plus-page keys (ink file named beside the note, page number recorded in the note) follow the note through renames because they are relative to the note, not to the PDF; recording the PDF's hash alongside the path allows re-finding the PDF after a move.
- "Export a flattened/annotated PDF copy" is the expected escape route in every sidecar design, and it is where PDFKit ink annotations or drawing into a PDF context belong, as a one-off whole-file write.

### Gaps
- How PDF Expert and Highlights store ink (they are believed to write standard annotations into the PDF) was not verified in this research.
- Okular's local annotation storage (docdata XML) was not reached.
- Zotero's behaviour when an attachment file is replaced (whether annotations stay attached by item key regardless of file hash) was not confirmed from documentation.
- No measurement of PDFKit save time for a multi-hundred-megabyte PDF was found.

## 5. Realistic data sizes and save cadence

### Takeaway
Hard numbers are thin: scanned textbooks run from tens of megabytes (bitonal) to more than a gigabyte (colour, 300 dpi), born-digital ones are typically a few megabytes to tens of megabytes, and the only library-size anecdotes found put a student's GoodNotes data at a few gigabytes. No trustworthy per-page byte size for a PKDrawing was found; the one relevant report shows why drawings must be split per page.

### Cited Findings

- Scanned page sizes at 300 dpi (vendor blogs and a court guide, low-quality sources, search summary): colour A4 about 1–3 MB (another source: 1–4 MB); greyscale about 400 KB–1 MB; a bitonal text page about 52 KB; a 100-page born-digital Word-made PDF "might be under 2MB"; doubling dpi roughly quadruples size. — [shrinkpdf guide](https://shrinkpdf.pages.dev/guides/en-54-scanned-pdf-large); [US District Court scanning tips](https://www.ned.uscourts.gov/internetDocs/cmecf/scanningtips.pdf)
- Extrapolation in the search digest from those per-page figures for a 500-page book: colour scan roughly 500 MB–1.5 GB, greyscale roughly 200–500 MB, bitonal roughly 15–30 MB (derived, not measured). — [shrinkpdf guide](https://shrinkpdf.pages.dev/guides/en-54-scanned-pdf-large)
- Goodnotes' free plan has a 5 MB import limit (pricing page, fetched 2026). — [Goodnotes pricing](https://www.goodnotes.com/pricing)
- Device-footprint anecdotes: a reviewer measured GoodNotes at about 2.33 GB (25 documents, up to 976 pages) and Notability at about 2.7 GB (2 notes of 600+ pages) on a 32 GB iPad; a TikTok post shows Goodnotes using 4.66 GB on a 64 GB iPad Air (both anecdotal, search summary). — [Gridfiti](https://gridfiti.com/goodnotes-vs-notability/); [TikTok](https://www.tiktok.com/discover/how-much-storage-does-good-notes-take)
- Exported-PDF anecdotes: about 10 handwritten pages exported at a minimum of 26 MB for one user and 1.8 MB for another; a Reddit thread attributes large exports to strokes and stickers being kept as vectors (anecdotal; exports, not native storage; search summary). — [Goodnotes feedback: file size](https://feedback.goodnotes.com/forums/191274-customer-suggestions-for-goodnotes-apple/suggestions/33581422-reduce-file-size); [Reddit mirror](https://reddit.zackpollard.pro/r/GoodNotes/comments/1ko7gx7/why_is_my_exported_goodnotes_pdf_so_large_any)
- Goodnotes support explains that the iCloud "Storage" figure is the total size of documents in iCloud while the larger device figure includes the app and temporary files (search summary). — [Goodnotes support](https://support.goodnotes.com/hc/en-us/articles/360004073756)
- PKDrawing scale warning: one developer reports a single notebook-scale PKDrawing file of about 27 MB that was rewritten on every save, with `dataRepresentation()` taking about 225 ms, fixed by using one PKDrawing per page; another app capped undo snapshots at 25 because serialised pages added up (search summary of GitHub PRs; the first PR page returned 404 when opened, so the figures are unverified). — [lazynotes PR #17](https://github.com/Jerenemy/lazynotes/pull/17); [Lemma-Notes-AI PR #91](https://github.com/kariemelsedfy/Lemma-Notes-AI/pull/91)
- Save cadence: PencilKit and PaperKit signal a change after each modification through a delegate (`PKCanvasViewDelegate`; `paperMarkupViewControllerDidChangeMarkup`), and Apple's sample saves on each callback; no debounce is prescribed. — [Apple: PKCanvasView](https://developer.apple.com/documentation/pencilkit/pkcanvasview); [WWDC25: Meet PaperKit](https://developer.apple.com/videos/play/wwdc2025/285/)
- Goodnotes auto-backup replaces the whole document copy in cloud storage on every edit. — [Goodnotes blog](https://www.goodnotes.com/blog/how-goodnotes-keep-your-digital-notes-safe)
- Zotero's contrast: syncing an annotation record is effectively instant, while a changed PDF means transferring the whole file, "many megabytes". — [Zotero KB](https://www.zotero.org/support/kb/annotations_in_database)

### Inferences
- With the change callback firing per stroke, a naive "write both files on every change" design rewrites the page's `.pkdrawing` and its PNG hundreds of times in a lecture. Under git each rewrite of a binary is a new full blob; the sync unit should therefore be "page closed" or "idle for N seconds", not "stroke ended", and history for ink binaries needs pruning or a store that does not keep every version.
- The data splits into two classes with opposite behaviour: PDFs are large, immutable and written once (ideal for content-addressed object storage or LFS, where history costs nothing because there is only one version); ink pages are small and rewritten constantly (where version churn, not size, is the cost).
- One drawing per page is the unit every source converges on (Goodnotes' `notes/<UUID>` per page, the 27 MB report, ilmi's `ink-03` naming).

### Gaps
- No reliable measurement of PKDrawing bytes per handwritten page, or of the PNG size of a page at 2×, was found. These are quick to measure on a device and should be measured rather than assumed.
- No sourced figure for the size of "a semester of handwritten notes" in GoodNotes or Notability native storage was found; only whole-app footprints.
- No authoritative statistics on typical textbook PDF sizes; the per-page figures come from low-quality sources.
- Goodnotes' and Notability's internal save or sync cadence is not documented.

## 6. Sync conflict handling for ink

### Takeaway
Three patterns exist in the wild: element-set merge with per-element versions and tombstones (Excalidraw; Goodnotes says CRDTs), server-authoritative ordering of record changes (tldraw), and whole-file or whole-page "keep both" copies (OneNote conflict pages, iCloud Drive version choice, Saber/Syncthing duplicates). Only the first two avoid user-visible conflicts, and both treat each stroke as an independently identified record.

### Cited Findings

- Excalidraw: union of elements by ID; higher `version` wins per element; equal versions broken by lower `versionNonce`; deletes are `isDeleted` tombstones so a deleted shape is not resurrected by a peer; tombstones are dropped on save to persistent storage (29 Mar 2020). — [Excalidraw blog](https://plus.excalidraw.com/blog/building-excalidraw-p2p-collaboration-feature)
- tldraw: the server room holds "the authoritative copy of the document"; running two room instances for one document means users "will overwrite others' changes"; a third-party analysis calls it optimistic concurrency with server-authoritative rebase, explicitly not a CRDT (docs fetched; analysis via search summary). — [tldraw docs](https://tldraw.dev/docs/sync); [Grida research note](https://grida.co/docs/wg/research/crdt/tldraw)
- Goodnotes: describes its approach only as CRDTs that merge changes from multiple users without merge conflicts, with event sourcing and local-first operation. — [web.dev](https://web.dev/case-studies/goodnotes); [Goodnotes blog](https://www.goodnotes.com/blog/behind-the-scenes-life-as-an-ios-engineer); [Swift.org](https://swift.org/blog/bringing-goodnotes-to-web-with-swift/)
- OneNote: conflicting edits produce a separate conflict page that the user reconciles by hand; merging works across different objects on a page but not the same object (forum, not official). — [Microsoft Support](https://support.microsoft.com/topic/3d7fd4e9-0fb9-4983-9853-b61b263b0f78); [Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/4882132/onenote-cannot-merge-changes)
- iCloud Drive documents: when versions conflict the user chooses which to keep and "Versions you don't select are deleted" on all devices (search summary of Apple Support). — [Apple Support](https://support.apple.com/guide/mac-help/document-versions-conflict-icloud-drive-mac-mh40780/mac)
- Saber over a generic file syncer: a user reported an unopenable note and a duplicate `note (2).sbn2` (anecdotal). — [Saber issue #1242](https://www.github.com/saber-notes/saber/issues/1242)
- Zotero: per-annotation records make sync "conflict-free"; the alternative is "an unresolvable file conflict, forcing the user to choose one side or the other". — [Zotero KB](https://www.zotero.org/support/kb/annotations_in_database)
- CloudKit provides record-version checks and leaves resolution to the app; a common default described is last writer wins (paper and a blog, search summary). — [CloudKit paper](https://www.vldb.org/pvldb/vol11/p540-shraer.pdf)
- PencilKit gives each stroke a UUID and erasing splits a stroke into new independent strokes. — [Apple: PKStroke](https://developer.apple.com/documentation/pencilkit/pkstroke-swift.struct); [WWDC20 session 10148](https://developer.apple.com/videos/play/wwdc2020/10148/)

### Inferences
- Handwriting on a page is close to an ideal add/remove set: strokes are created once, rarely modified (move/resize/recolour via lasso being the exceptions), and deleted. The Excalidraw scheme (ID, version, tombstone) is the smallest documented design that merges two divergent copies of such a set deterministically without a server.
- For a single student using devices one at a time, the realistic conflict is "wrote on the iPad offline, then wrote on the same page on another device before syncing". A stroke-ID union resolves that with no loss; whole-file last-writer-wins silently drops one device's strokes; "conflict copy" preserves both but hands the user a manual merge.
- A stroke-set merge for PKDrawing needs deletions to be recorded somewhere (a tombstone list of stroke UUIDs beside the drawing, or a common ancestor to diff against); the PKDrawing blob alone does not say whether a missing stroke was erased or never seen. Git supplies the common ancestor for a three-way merge, which a custom merge driver could use by decoding all three blobs on an Apple device; that merge can only run where PencilKit exists.

### Gaps
- What Goodnotes and Notability do, concretely, when the same page is edited offline on two devices (union, last writer wins, duplicate) is not documented in any source found; no user reports were located either way.
- Apple Notes' behaviour for the same case was not found.
- No published design was found that applies an add/remove set specifically to PKDrawing strokes.

## 7. What a student needs from a GoodNotes replacement, in priority order, and what PencilKit supplies

### Takeaway
The review literature in 2026 frames the choice by study workflow, and the features that recur as decisive are: fluent pen/highlighter/eraser writing on PDFs and notebook pages, lasso with move/resize, organisation (folders, tabs, bookmarks), handwriting search, and study tools (Goodnotes Study Sets, tape) with audio as Notability's differentiator; PencilKit supplies the writing core and selection for free, while everything document-level (pages, templates, PDF layer, search index, zoom window, export, flashcards) must be built. No ranked survey of student priorities was found; the ordering below is assembled from reviews and is a judgement.

### Cited Findings

- Feature set the Paperlike review compares (Aug–Oct 2026, fetched): pen, pencil, highlighter, eraser, lasso, text box, shapes, ruler, tape; handwriting search/OCR, handwriting-to-text, math conversion; nested folders, document tabs or split view, per-page templates, bookmarks, import; audio sync, transcription, flashcards/Study Sets, exam practice, AI study tools; iCloud, auto-backup, collaboration, export, sync. Its framing: "For students, the real question isn't 'Which is better?' It's 'How do I review?'"; handwriting search is absent from both apps' free plans. — [Paperlike](https://paperlike.com/blogs/paperlikers-insights/app-review-goodnotes-vs-notability)
- 2026 comparisons position Goodnotes for structured course organisation and exam prep, Notability for lecture capture with audio synced to handwriting (search summary of several reviews, mostly vendor or affiliate sites). — [Setapp](https://setapp.com/app-reviews/goodnotes-vs-notability); [KDigitalStudio](https://kdigitalstudio.com/blogs/news/goodnotes-vs-notability-2026-best-ipad-note-taking-app)
- One blogger's most-used Goodnotes features: the lasso tool (selects handwriting, images and text boxes separately and resizes them) and the zoom window, used "almost constantly" for handwritten notes (single blog, anecdotal, search summary). — [KDigitalStudio: favourite features](https://kdigitalstudio.com/blogs/news/favorite-goodnotes-features)
- Goodnotes plan gates show what the vendor considers baseline versus premium: free = 3 files, 5 MB import, 20 minutes audio; Essential = unlimited files and audio; Pro = cross-platform sync, collaboration, AI. — [Goodnotes pricing](https://www.goodnotes.com/pricing)
- Goodnotes search covers handwriting, typed text and PDF text but does not OCR imported PDFs. — [Goodnotes help: Search](https://goodnotes-team.notion.site/Search-Handwriting-and-Math-Recognition-26fb740273d281b5beb8e60130afb556)
- An App Store reviewer complaint: text boxes are awkward for type-heavy work (anecdotal, search summary). — [App Store listing](https://apps.apple.com/pa/app/goodnotes-ai-notes-docs-pdf/id1444383602?uo=2)
- What PencilKit provides without app code: the canvas with Apple's low-latency ink rendering and Pencil handling; the tool picker with inks, colour picker and eraser; ruler (`isRulerActive`); drawing policy (pencil-only versus finger); smart selection (tap word/line, brush-select), Insert Space; scroll/zoom because the canvas is a scroll view; undo through the responder chain; rendering to image or CGContext. — [Apple: PKCanvasView](https://developer.apple.com/documentation/pencilkit/pkcanvasview); [WWDC20: What's new in PencilKit](https://developer.apple.com/videos/play/wwdc2020/10107/); [Apple: PKDrawing](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct)
- What PaperKit adds (iOS/iPadOS/visionOS 26, macOS 26): shapes, images, text boxes and an insertion menu on top of PencilKit drawing, with its own data container. — [WWDC25: Meet PaperKit](https://developer.apple.com/videos/play/wwdc2025/285/)
- What PencilKit does not provide on the Mac: the tool picker is unsupported on Mac Catalyst and PKCanvasView does not exist for AppKit. — [WWDC20: What's new in PencilKit](https://developer.apple.com/videos/play/wwdc2020/10107/); [Apple: PKCanvasView](https://developer.apple.com/documentation/pencilkit/pkcanvasview)
- Handwriting recognition on stroke data is what Notes itself does ("This is what we do for handwriting recognition in Notes"), and for image-based recognition Apple points to rendering the drawing to images. — [WWDC20 session 10148](https://developer.apple.com/videos/play/wwdc2020/10148/)

### Inferences
A priority order as users appear to experience it, with the build status for a PencilKit-based app (judgement, assembled from the sources above):

1. Writing feel on a page (pen, highlighter, eraser, undo, palm rejection, finger-scroll): PencilKit, free.
2. Writing directly on PDF pages, with the page staying sharp when zoomed, across a whole 500-page book: build (page layer under the canvas, one drawing per page, page virtualisation).
3. Blank/ruled/grid notebook pages and page templates: build (templates are just background images or PDFs under the canvas).
4. Lasso: select, move, resize, recolour, cut/copy between pages: PencilKit gives lasso and smart selection inside one canvas, free; cross-page and cross-note paste needs app work.
5. Sync that is fast and never loses a page: build; this is where both incumbents have had the most complaints and have rebuilt.
6. Page management (add, delete, reorder, duplicate pages; thumbnails grid): build.
7. Organisation and navigation (folders, tabs, bookmarks, PDF outline): ilmi's folder-of-Markdown model covers folders; outline and bookmarks are build.
8. Handwriting search: build. No public PencilKit recognition API was found; the route is rendering each page and running text recognition, then indexing. Goodnotes' own gap (no OCR of imported scans) is an opening.
9. Shapes (draw-and-hold snapping), typed text boxes, images on the page: PaperKit supplies these on OS 26; otherwise build.
10. Zoom window for writing small at the bottom of a page: build (not found in PencilKit).
11. Export to PDF (flattened ink over the original page): build, using PKDrawing rendering into a PDF context.
12. Split view or two documents side by side: partly the OS (iPad multitasking), partly build.
13. Flashcards and spaced repetition (Goodnotes Study Sets, tape): ilmi's existing core; this is where ilmi is already ahead.
14. Audio recording synced to strokes: Notability's differentiator, not a GoodNotes parity item; stroke time offsets in PKStrokePoint make it feasible later.
15. Collaboration and AI features: Goodnotes Pro features; out of scope for a single-student replacement.

- Adopting PaperKit instead of bare PencilKit would cover item 9 and give a native Mac editing surface, at the cost of requiring OS 26 and of storing a PaperMarkup blob (a second opaque Apple format) rather than a PKDrawing.

### Gaps
- No survey or ranked data on which GoodNotes features students use most was found; Reddit threads were not reachable through search. The ordering above is inference.
- Goodnotes' official full feature list (zoom window, shapes tool, element stickers, outlines) could not be fetched from the vendor's support site (403); those features are known from reviews rather than verified vendor text here.
- Whether PKCanvasView exposes shape recognition to third-party apps was not confirmed.

## 8. Large PDFs: pdf.js in WKWebView versus native PDFKit on iPad

### Takeaway
A web renderer runs inside WKWebView's separate WebContent process, which has a hard, undocumented, device-dependent memory ceiling the app cannot raise and which is killed silently when exceeded; canvas memory has its own cap. Reports of pdf.js failing on large or scanned PDFs on iOS are common, while PDFKit runs in the app's own process but has its own per-page analysis and memory costs. Opening 500-page scanned textbooks smoothly points to native rendering (PDFKit or CGPDF tiles) or to very disciplined page virtualisation in pdf.js.

### Cited Findings

- WebContent memory limits (WebKit Bugzilla 268816, comment by Ben Nham, 13 Mar 2024, fetched): "On iPhones, for most devices, the limit is 1.5GB" (it may be exceeded when the system is not under pressure); "On iPad, the WebContent process has a higher memory limit, which differs by device"; "For an 8GB device, the limit will be in the 4GB+ range"; the Gigacage for typed arrays supported 2 GB on iOS at the time and was later enlarged; another WebKit commenter: "I do not think that this is documented by Apple". The bug's own title reports an 8 GB iPad offering only 1.88 GB to a page through typed arrays. — [WebKit Bugzilla 268816](https://bugs.webkit.org/show_bug.cgi?id=268816)
- The limit cannot be raised by the app, and the increased-memory-limit entitlement applies to the app's process, not WebContent (forum answer and a GitHub report, search summary). When WebContent is killed the app gets no memory warning; it must handle `webViewWebContentProcessDidTerminate` (blog, search summary). — [Apple Developer Forums 133449](https://developer.apple.com/forums/thread/133449); [musetric issue #1052](https://github.com/musetric/musetric/issues/1052); [Never Meant: handling blank WKWebViews](https://nevermeant.dev/handling-blank-wkwebviews/)
- Canvas limits on iOS: a react-pdf issue reports "Total canvas memory use exceeds the maximum limit (384 MB)", with a related report citing 224 MB; mitigations were lowering render resolution and rendering only visible pages (search summary; figures vary by iOS version and device). — [react-pdf issue #1020](https://github.com/wojtekmaj/react-pdf/issues/1020)
- An Apple forum thread on WKWebView canvas memory describes rendering problems in continuous mode with a 224 MB PDF on iPhone that did not appear on iPad (search summary). — [Apple Developer Forums 683573](https://developer.apple.com/forums/thread/683573)
- A commercial competitor's benchmark says pdf.js renders a page onto a single large canvas that may exceed what the browser permits, struggles with large embedded JPEGs, and quotes a customer who found pdf.js on iPad unable to open PDFs over 100 MB (vendor source with an interest; search summary). — [Apryse](https://apryse.com/blog/pdf-js/pdf-js-reliability-benchmark)
- A Cordova developer reported WebContent crashes with pdf.js in WKWebView attributed to memory peaks and reduced canvas size and resolution (2022 chat digest, search summary). — [Cordova Slack digest](https://apache.googlesource.com/cordova/+/c01aeaf4a5d91c23167638f9e4bcd886d15823a6/slack-digest/2022-03-14.md)
- PDFKit costs: a 2026 GitHub issue (measured on macOS) reports that a PDFView showing image-only pages triggers document analysis (text recognition) on each newly shown page, about 0.7 s of CPU and about 2.5 MB of memory per page, with no public API found to disable it; an older Apple forum thread reports PDFPage memory growing by 30 MB+ per page while swiping (search summary). — [bookside issue #34](https://github.com/NomaDamas/bookside/issues/34); [Apple Developer Forums 97515](https://developer.apple.com/forums/thread/97515)
- Goodnotes renders with its own engine on Metal (iOS) and WebGL (web) rather than a web PDF viewer on iOS. — [Swift.org](https://swift.org/blog/bringing-goodnotes-to-web-with-swift/)

### Inferences
- The risk with pdf.js is not the PDF's file size as such but peak memory for decoded page images and canvases inside a process whose ceiling is unknown and silent on failure. Scanned textbooks are the worst case because each page is a large image.
- If ilmi keeps pdf.js, the requirements are: range-loading rather than reading the whole file into a JS array (the typed-array ceiling), a small fixed pool of page canvases, capped device-pixel-ratio, and a recovery path for WebContent termination.
- A native page layer (PDFKit `PDFPage` thumbnails/tiles or CGPDF drawing) beneath a native PencilKit canvas keeps both the PDF and the ink out of the WebContent process and aligns with the planned Swift plugin; it also matches how the incumbents work. On macOS the same PDFKit code is available.
- PDFKit is not free of problems (per-page analysis on scans, historical leaks), so the native route still needs measurement on a real 500-page scan.

### Gaps
- No current (iPadOS 26) authoritative figures for the WebContent memory limit or the canvas memory cap per iPad model were found; the WebKit figures are from 2024 and are stated by engineers in a bug thread, not documentation.
- No head-to-head benchmark of pdf.js in WKWebView against PDFKit on iPad for large scanned PDFs was found.
- No report was found of pdf.js being used successfully or unsuccessfully inside a Tauri iOS app specifically.
